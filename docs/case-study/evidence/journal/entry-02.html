2026-11-12 18:20 — Design chosen; first working v3 slice rendered
  • Options weighed: (A) role tabs Protocol/Implementation/Review as in the mockup; (B) one window per delegation with 1–3 panes; (C) one worker per tab, named after its task.
  • Chosen: C. One worker = one tmux window = one full-size transcript; tab name is the first clause of the goal the parent wrote; state is a coloured glyph in the tab (● running, ◐ silent, ✓ done, ✗ failed); the overview window is named "agents" and carries a badge (●3 ✗1).
  • Why not A: Hermes records no role for a task. Role tabs would need a classifier guessing from prose — explicitly out of scope, and wrong labels are worse than none. Why not B: three tasks in one delegation breaks the two-pane ceiling or splits siblings anyway; a tab's state becomes an aggregate; pairing needs slot packing and tiled reflow. C deletes that machinery and stays under the ceiling.
  • Lifecycle (the real fix for "history dominates"): a tab exists only for work live since the workspace came up. Finished tabs linger 5 min after they settle or were last viewed, never close while in view, and a tab the user closes stays closed (v2 recreated it). Failures keep their tab until looked at; looking is the acknowledgement. Old failures no longer light a permanent "!".
  • Overview: table replaced by three sections — RUNNING (task title, then model · elapsed · tools · current call), NEEDS ATTENTION (failure reason + last error), RECENT (one dim line each, capped by pane height). Ids demoted to a dim handle for hermes-tmux open <id>.
